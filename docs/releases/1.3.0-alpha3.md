# winTerm 1.3.0-alpha3

**This is an alpha prerelease for local testing. It is not a stable release.**
The current stable release remains
[v1.2.0](https://github.com/HelloThisWorld/winTerm/releases/tag/v1.2.0), and
`/releases/latest` continues to point there. This alpha is published only as a
tagged GitHub prerelease; it is not listed on the winTerm website and is not
submitted to WinGet.

winTerm 1.3.0-alpha3 fixes the five issues reported from local testing of
[1.3.0-alpha2](https://github.com/HelloThisWorld/winTerm/releases/tag/v1.3.0-alpha2).
The Command Timeline feature set is otherwise unchanged.

## Changes since alpha2

- **No more stray `\` characters before the prompt.** The shell integration
  module terminated every escape sequence with two characters instead of one,
  so the terminal printed a leftover backslash per emitted mark — three before
  the first prompt and four after each command.
- **The Timeline records exactly the typed command.** The prompt marks were
  written as console side effects, which the console host prints before a
  prompt function's returned text, so the command-start mark landed before the
  visible prompt: entries read like `\PS C:\Users\you> cd`, and Load inserted
  that whole text. The marks are now embedded in the returned prompt string in
  FinalTerm order, so entries contain only what you typed, Load inserts only
  the command, and completed commands resolve to ✓/✕ status instead of
  staying Unknown.
- **No progress bar at an idle prompt.** A shell-integrated pane no longer
  animates the Visual Progress bar while waiting for input; the bar appears
  when a command actually executes and clears at the next prompt.
- **No phantom Timeline row.** The active prompt no longer produces a
  `Command text unavailable` / `Running` entry. An entry appears when a
  command executes.
- **No row jitter.** Moving the selection with the arrow keys or hovering
  with the mouse no longer makes Timeline rows jump; selection changes reuse
  the existing rows.
- **Quieter startup under strict antivirus.** If an antivirus engine blocks a
  module component at parse time (observed for `Compatibility.ps1`), the
  session no longer shows a red parse error. The component is skipped, the
  optional compatibility commands are simply absent, shell integration still
  works, and `Get-WinTermShellDiagnostics` reports the redacted failure.

## Command Timeline overview

The Command Timeline is a per-pane, in-memory list of the commands that pane
has run, built from OSC 133 shell integration only. Open it with `Ctrl+Tab`,
or with the thin handle on the left edge of the terminal. Bare PowerShell
profiles get shell integration automatically; see the
[1.3.0-alpha2 release notes](https://github.com/HelloThisWorld/winTerm/releases/tag/v1.3.0-alpha2)
for the auto-integration rules and the
[1.3.0-alpha1 release notes](https://github.com/HelloThisWorld/winTerm/releases/tag/v1.3.0-alpha1)
for the full keyboard map.

## Settings

```json
{
  "commandTimeline.enabled": true,
  "commandTimeline.historyLimit": 500
}
```

Per profile:

```json
{
  "shellIntegration.autoInject": true
}
```

An existing settings file needs no migration.

## Privacy

- Command text lives only in memory, only in the pane that ran it, and only
  while that pane is open. Nothing is written to disk; there is no command
  history file or database.
- Command output is never cached, indexed, or searched.
- Filter text is never saved and never leaves the pane.
- No telemetry is written, and no command, output, path, or filter text is
  logged.
- The clipboard is written only by an explicit copy action, and is never read.

See the [privacy policy](https://github.com/HelloThisWorld/winTerm/blob/main/PRIVACY.md).

## Unchanged in this release

Workspace schema (2), docking model (1), shell protocol (1), theme schema (1),
update manifest schema (1), package identity, and signing policy are all
unchanged from v1.2.0.

## Known limitations

- The Timeline requires OSC 133 shell integration; it stays unavailable under
  `cmd.exe`.
- A multi-line command is refused when the shell has not enabled bracketed
  paste, because unbracketed line breaks would be read as pressing Enter.
- Loading a command longer than 1024 characters asks for a confirming `Enter`.
- Command history does not survive closing a pane, and is intentionally never
  persisted.

## Installation

The Setup EXE supports current-user and all-users installation; the Portable
ZIP can be extracted to a writable directory and run without installation.
Installing alpha3 over an earlier alpha is supported; the file version
advances to `1.3.0.2`.

Publisher: `helloThisWorld`. Tag: `v1.3.0-alpha3`.

## Signing

The winTerm 1.3.0-alpha3 Setup EXE is not Authenticode-signed. Windows may
display Unknown Publisher or a SmartScreen warning. Download only from the
official GitHub Release and verify the file against `SHA256SUMS.txt` before
running it.
